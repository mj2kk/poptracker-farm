# ТЗ для Codex: Этап 1 — Android Agent Connectivity MVP

**Проект:** PopTracker Device Cloud  
**Зависимость:** прочитать [общее описание проекта](../01-PopTracker-Device-Cloud-Project.md) до начала работы.  
**Цель:** собрать устанавливаемый APK и подключить один реальный Android к Control Server **без USB во время работы**, используя исходящие HTTPS-запросы.

## 1. Режим работы Codex

Ты выступаешь инженером-исполнителем. Сначала исследуй фактическое окружение, затем реализуй минимальное работающее решение. Не переписывай существующий PopTracker, не изменяй таблицы TikTok и не отключай текущий парсер. Показывай результаты команд, не утверждай, что устройство подключено, если это не подтверждено серверными логами и экраном APK.

Если отсутствуют критические данные (доступ к серверу, домен, Android SDK, устройство), реализуй доступную часть и явно перечисли блокеры. Не придумывай IP, пароли, домены и версии Android.

## 2. Инвентаризация до написания кода

1. Найди репозиторий PopTracker и проверь стек, структуру, конфигурацию, существующие API и тесты.
2. Проверь доступность Android Studio/Gradle/JDK/Android SDK и возможность сборки APK.
3. При подключённом Android через `adb devices -l` получи модель, Android API level и ABI. USB допустим для диагностики и первоначальной установки, но не должен требоваться для дальнейшего обмена данными.
4. Проверь доступный Ubuntu-сервер, способ деплоя, домен и HTTPS. Не публикуй секреты в отчёте.
5. Составь краткий план с путями файлов и перечнем минимальных изменений. При обнаружении конфликта с существующим проектом остановись и опиши его.

## 3. Архитектура MVP

```text
Android APK (Kotlin)
    ├─ UI: статус, device ID, последний heartbeat, ошибка
    ├─ Registration client
    ├─ HTTPS heartbeat client
    └─ Local secure credential storage
             │ outbound HTTPS
             ▼
Laravel Control API
    ├─ Device enrollment
    ├─ Device heartbeat
    ├─ Device status (operator only)
    └─ MySQL: device_agents, device_heartbeats (или эквивалент)
```

**Важно:** на этом этапе использовать HTTPS polling/heartbeat, **не WebSocket**. Это упрощает проверку сети и работу за NAT. Не реализовывать произвольные удалённые команды.

## 4. Серверная часть

Предпочтительно интегрировать отдельным модулем в существующий Laravel. Если его нет или интеграция опасна, создать изолированный сервис и обосновать выбор.

### Минимальный контракт API

- `POST /api/device/v1/enroll` — первоначальная регистрация по одноразовому enrollment code; возвращает `device_id` и уникальный device token. Код короткоживущий, одноразовый, генерируется только оператором; нельзя использовать открытый анонимный enrollment.
- `POST /api/device/v1/heartbeat` — Bearer device token, тело `{device_id, agent_version, android_version, battery_percent?, sent_at}`. Сервер проверяет соответствие токена устройству и обновляет `last_seen_at` по **серверному времени**.
- `GET /api/device/v1/me` — авторизованный запрос устройства, возвращает его идентификатор и статус.
- Операторская команда/защищённый endpoint для просмотра зарегистрированных устройств, `last_seen_at` и статуса. Не делать публичный список устройств.

Форматы ответа, ошибки и версионирование API зафиксировать в `docs/device-api.md`. Не возвращать токены в логах и повторных GET-ответах.

### Хранение

Минимальные сущности:

- `device_agents`: UUID, display_name, token_hash, agent_version, android_version, status, last_seen_at, created_at, revoked_at.
- `device_heartbeats`: id, device_id, received_at, battery_percent nullable, diagnostics nullable. Для MVP предусмотреть разумное ограничение хранения истории.
- Одноразовые enrollment codes: только хеши, срок действия, использованность, привязка к оператору при наличии.

Не хранить device token в открытом виде на сервере. Секреты не должны попадать в git. Миграции должны быть обратимыми и не затрагивать существующие таблицы PopTracker.

## 5. Android-приложение

- Kotlin + минимальный UI (Compose либо обычный Activity, выбери проще для имеющегося SDK).
- Экран настройки адреса сервера (только HTTPS для реального подключения), ввода enrollment code, кнопка `Connect`, состояние регистрации, `device_id`, время последнего успешного heartbeat, понятное сообщение об ошибке.
- После регистрации безопасно хранить токен в приватном хранилище приложения с использованием Android Keystore для защиты ключевого материала. Не записывать токен в Logcat.
- Heartbeat каждые ~60 секунд **пока приложение открыто/активно**. Использовать тайм-ауты, exponential backoff с jitter и ограничение частоты повторов.
- Предусмотреть кнопку `Disconnect / Forget device` с удалением локальных credentials; серверный отзыв токена выполняется отдельно оператором.
- Минимальные разрешения: `INTERNET`, `ACCESS_NETWORK_STATE` при необходимости. **Не запрашивать** Accessibility, MediaProjection, ADB, root, VPN и доступ к файлам.
- Не обещать гарантированную работу при закрытом приложении: постоянный foreground service и восстановление после reboot являются отдельной задачей после успешного MVP.

## 6. Безопасность

- Только HTTPS с корректной проверкой сертификата; не отключать TLS validation и не принимать все сертификаты.
- Enrollment code короткоживущий и одноразовый; предусмотреть защиту от перебора и rate limiting.
- Bearer token генерируется криптографически стойко, отдельно для каждого устройства; поддерживается отзыв.
- Не отправлять IMEI, телефонный номер, аккаунты TikTok и другие ненужные персональные данные.
- Не использовать постоянный общий пароль для всех агентов.
- Логи без токенов и других секретов.

## 7. Сборка и проверка

1. Собери debug APK; запиши точный путь и SHA-256. Не подписывай release APK фиктивным или случайным ключом.
2. Установи APK на один Android (для установки можно временно использовать USB).
3. Отключи USB, оставь телефон в Wi-Fi или мобильной сети.
4. Введи адрес сервера и одноразовый код, зарегистрируй устройство.
5. Убедись, что `GET /me` проходит, а сервер получает минимум 3 heartbeat с интервалами около 60 секунд.
6. На 2–3 минуты отключи сеть Android, затем включи; проверь автоматическое восстановление связи без USB и без перезапуска сервера.
7. Проверь ошибку неправильного кода, истёкшего кода, неверного токена и недоступного сервера.
8. Убедись, что в серверных и Android-логах нет секретов.

Если физическое устройство или сервер недоступны, не отмечай соответствующие тесты пройденными. Отдельно укажи, что проверено локально, а что требует ручного действия.

## 8. Автоматические тесты

- Сервер: регистрация с валидным/просроченным/повторно использованным кодом; heartbeat с валидным/отозванным токеном; защита списка устройств; обновление last_seen_at.
- Android: тест сериализации запросов и обработки сетевых ошибок, если окружение позволяет.
- Не требовать полного E2E без доступного физического устройства.

## 9. Результаты, которые нужно передать

1. Исходный код Android Agent и серверных изменений.
2. `app-debug.apk` (или путь к реально собранному APK).
3. `docs/device-api.md` с примерами запросов без настоящих секретов.
4. `docs/setup.md`: как развернуть сервер, выпустить enrollment code, установить APK, подключить устройство.
5. `docs/step-01-report.md`: окружение, выполненные команды, результаты тестов, скриншоты/логи без секретов, нерешённые проблемы, следующий шаг.

## 10. Definition of Done

Этап считается завершённым **только если** APK установлен на физический Android, USB отключён, устройство зарегистрировано через HTTPS, сервер зафиксировал минимум три heartbeat, а после краткого разрыва сети связь восстановилась автоматически при открытом приложении.

Если собран только APK и API, статус этапа: **частично выполнен**.

## 11. Что не делать

- Не реализовывать TikTok scraping в рамках этапа 1.
- Не добавлять AccessibilityService, OCR, скриншоты, управление экраном или выполнение shell-команд.
- Не переносить и не переписывать текущий ADB-парсер.
- Не внедрять Redis, WebSocket, сложную панель управления или автоматическое обновление APK.
- Не вносить необратимых изменений в существующую БД.
- Не обходить системные ограничения Android или защиту сторонних сервисов.

**Начни с инвентаризации и краткого плана, затем приступай к реализации, если окружение позволяет.**
